# motology.ai frontend: design handoff

This is the buyer-facing web app for motology.ai (Next.js 15, React 19, Tailwind).
It is a snapshot of the `motology/` folder from the `motology.ai` branch
(PR #1643). `screenshots/` has every screen on desktop and phone, plus dark
mode, so you can review without running anything.

## Run it locally (no backend needed)

Requires Node 22.12 or newer.

```bash
# 1. Start the mock backend (canned cars, chat replies and a deal). Port 8099.
node mock-gateway/server.mjs

# 2. In a second terminal, from this folder:
npm install
cp apps/web/.env.example apps/web/.env.local
#    then edit apps/web/.env.local:
#      MOTOLOGY_GATEWAY_URL=http://localhost:8099
#      MOTOLOGY_API_KEY=dev-key        (any value works with the mock)
npm run dev
```

Open http://localhost:3000. Pages to look at:

| Page | URL |
|---|---|
| Home | `/` |
| Search | `/search` |
| Vehicle | `/vehicle/T2201` |
| Chat (from a car) | `/chat?stock=T2201`, then tap "Is this a fair price?", type an offer like "I would offer 34000", then "connect me with the dealer" |
| Deal summary | "Open full deal summary" in the deal panel after chatting |
| Buyer confirmation (dealer contact, test drive) | `/confirm/cr_demo_abcdefghijkl` |
| Not found | `/vehicle/NOPE` |

The mock always answers the same way. The numbers are illustrative, not real
market data.

## Where the design lives

| What | Where |
|---|---|

| Header and footer | `apps/web/components/site/` |
| Home page and the animated hero demo | `apps/web/app/page.tsx`, `apps/web/components/home/` |
| Search and vehicle cards | `apps/web/app/(buyer)/search/`, `apps/web/components/search/`, `apps/web/components/vehicle/` |
| Vehicle page | `apps/web/app/(buyer)/vehicle/[id]/page.tsx` |
| Chat, deal panel, ZIP control, decision card | `apps/web/components/chat/` |

Font: Inter, bundled locally (`@fontsource-variable/inter`), no Google Fonts call.
Brand green is `--brand`; the lime accent is `--accent`. Both have dark-mode values.

## Rules to keep when redesigning

These are product and legal requirements, not style choices. Please check with
engineering before changing them.

1. **The frontend never invents a number.** Every price, offer, fee and score
   comes from the backend. A missing value shows as "—". Do not add example
   prices to live screens (the home-page demo is labelled "Example").
2. **Consent stays explicit.** On the confirm page the consent checkbox is never
   pre-ticked, and the disclosure text is shown exactly as the backend sends it.
3. **Privacy wording is precise.** The opening offer and good price stay private.
   The walk-away does not, because the dealer's sales assistant is told not to
   quote above it. Keep the copy as specific as it is now.
4. **Honest states.** Screens for "no market data", "fees unavailable", "prices
   are for another ZIP", "couldn't load your saved deal" and the test-drive
   outcomes (booked, requested, unavailable) must keep saying what is true.
5. **Accessibility.** The current build passes an axe-core audit with 0 violations
   on every page, in light and dark, on desktop and phone. Keep the colour
   contrast, focus states, labels and reduced-motion support.

## Checks engineering runs

From this folder: `npm run type-check`, `npm run lint`, `npm test`, `npm run build`.
Changes come back through the repo (PR #1643, branch `motology.ai`) so these
run in CI.

## Not included

`node_modules`, build output and env files are left out. The rest of the
platform (the AutomotiveAI backend, the pricing engine and the CRM) is a
separate part of the repo and isn't needed for UI work.
